## 5. Privacy model

- **Planning requests:** Vizier sends your app idea, questionnaire answers, and
  a *summary* of your workspace (package metadata, README excerpts, existing
  agent-rule files) to the LLM provider you select (Anthropic, an
  OpenAI-compatible API, or omniroute). **No full source-code files are sent
  during planning.** Provider choice determines where data is processed and is
  subject to that provider's privacy/retention policy and terms.
- **Plan-progress monitoring:** runs **entirely on your local machine**. It
  inspects file existence and task-id references only. **No repository data,
  source code, or file contents are transmitted** to any LLM or external
  service.
- **Optional AI narrative:** if enabled, the progress narrative is generated
  from **plan metadata only** (task ids, titles, status counts) — never from
  your code.
- `vizier.codePrivacyMode` (default `true`) is a guarantee that Vizier will not
  transmit repository source code to any LLM.
- **Optional tracker sync** (`vizier.planTrackerWebhook`): if configured, the
  *progress report* (task ids, titles, status counts, verification signals) is
  POSTed to that URL. This is plan metadata only — **never source code**.
- **Response caching** stores hashed request/response pairs locally to reduce
  cost and improve reproducibility; no prompts leave your machine via caching.
- API keys are stored in VS Code Secret Storage. They are **not** written to
  plaintext settings.

## 8. Accuracy of progress reports

Progress monitoring is **heuristic**:
- A task is "done" when all of its expected files exist.
- "in_progress" when some expected files exist or the task id is referenced in
  the repo.
- "blocked" when its dependencies are not done.
- "verified" when done **and** backed by git commits or by tests that
  **actually passed** (parsed from Jest/JSON or JUnit/XML artifacts). A
  failing suite prevents "verified". This is a signal of implementation
  activity + green tests, **not** proof the feature is correct or safe.
- **Acceptance criteria and test outcomes are NOT auto-verified.** A green
  progress bar does **not** mean the feature works. Confirm by running your own
  tests, CI, and code review. Coverage percentages (if a report is present) are
  project-wide and are not mapped to individual tasks.
